# 정답 기포장 q″ → Cooper 비교 점검 (10/7)

정답 기포장 레포(`tpgk4456-ui/bubbleml-poolboiling-analysis`)가 확정한 열유속을
이 저장소의 Cooper 역산에 넣고, 나온 벽 과열도를 정답 과열도와 비교했더니
`불일치`가 나왔다는 보고를 점검한 기록이다.

- 입력 값: 정답 기포장 보고서 `ground_truth_report.pdf` 2·5·8쪽
  → `data/ground_truth/ground_truth_final_snapshot.csv`
- 재실행: `python scripts/run_gate.py --config configs/ground_truth.yaml`

| 조건 | ΔT_sup 정답 [K] | q″ 산술 [kW/m²] | Cooper ΔT [K] | 상대오차 | 처방 사이트 수 |
|---|---|---|---|---|---|
| Twall 80 | 22 | 39.0 | 17.56 | −20.2% | 10 |
| Twall 86 | 28 | 58.5 | 20.08 | −28.3% | 16 |
| Twall 90 | 32 | 69.4 | 21.24 | −33.6% | 20 |
| Twall 94 | 36 | 81.6 | 22.41 | −37.8% | 24 |
| Twall 100 | 42 | 97.9 | 23.80 | −43.3% | 30 |

평균 오차(MAPE) **32.6%**, log-log 기울기 **0.700**. 보고된 표와 소수 첫째 자리까지 같다.

**코드 버그는 아니다.**

- 열유속 정의를 바꿔도 결과는 같다. 기울기는 네 정의 모두 0.69~0.71이다.

## 2. 왜 생기나

### 2-1. 기울기 기준이 Cooper가 아니라 사이트 처방을 잰다

| 관계 | 지수 | R² |
|---|---|---|
| q ∝ ΔT^a (정답 비등곡선) | 1.42 | 0.994 |
| N ∝ ΔT^b (설정 파일의 사이트 수) | 1.70 | 0.995 |
| q ∝ N^c | 0.84 | **0.9997** |

열유속은 사이트 수 하나로 거의 다 설명된다(R² 0.9997). 사이트당 열유속은
3.9 → 3.3 kW/m²로 거의 일정하다. 그런데 사이트 수는 시뮬레이션 **입력**이다.
그래서 `a ≈ b·c`인 비등곡선 기울기는 누가 사이트를 몇 개 넣었는지로 정해진다.
Cooper는 실제 표면에서 과열도에 따라 사이트가 저절로 늘어나는 효과를 담고 있고,
그 결과 `q ∝ ΔT^3.03`을 가정한다. 1.42와 3.03이 다른 것은 상관식의 실패라기보다
처방 방식의 차이다. 보고서 8쪽과 노션 `정답 기포장 문제 해결` 제안이 내린 결론과 같다.

### 2-2. 평균 오차(MAPE)도 같은 원인에서 나온다 — 기울기만 빼서는 안 끝난다

- 조건별 오차는 처방 사이트 수와 **완전히 같은 순서**로 커진다(순위상관 ρ = −1).
- 그래서 MAPE도 어느 과열도 범위를 골랐는지에 달려 있다.
  22~28 K만 보면 24.2%, 32~42 K만 보면 38.2%다.
- Cooper를 정방향으로 돌려 보면 같은 과열도에서 실제 표면은 77 / 160 / 240 / 343 / 548 kW/m²를 낸다.
  BubbleML은 그 0.51 → 0.18배만 낸다. 사이트가 실제 표면보다 점점 더 모자란 셈이다.
- 같은 물성으로 Zuber 임계열유속을 계산하면 약 143 kW/m²다. Cooper 표면은 ΔT ≈ 27 K에서
  이미 여기에 닿는다. BubbleML의 28~42 K 조건은 사이트가 적은 덕분에 핵비등에 머문다.
  Cooper 기준으로는 핵비등 적용 범위를 넘은 과열도다(문헌 대표 물성으로 본 크기 점검이다).

### 2-3. 정리

이 다섯 조건으로는 Cooper의 **기울기(형태)를 검증할 수 없다.** 검증할 수 있는 것은
"이 열유속이면 과열도가 몇 도인가"라는 **조건별 크기**뿐이다. 그 크기에도 사이트 처방의
추세가 섞여 있다는 점을 같이 적어 둬야 한다.

## 3. 무엇을 고쳤나

1. **정답 표 입력 경로** — `ground_truth.csv`를 주면 HDF5를 다시 읽지 않는다.
   정답 기포장 레포가 확정한 q″를 그대로 Cooper에 넣는다. 다른 식으로 다시 뽑으면
   "정답 열유속"이 두 개가 되기 때문이다. 컬럼 이름은 보고서 13쪽 정의를 따랐다.
   조건이 열로 놓인 표도 읽는다. 값이 빈 조건이 있으면 빼지 않고 멈춘다.
2. **기울기 기준의 역할** — 새 설정 `gate.slope_role: auto`.
   표에 조건별 처방 사이트 수(`input_n_sites_prescribed`)가 있고 그 수가 조건마다 다르면
   기울기는 **참고만** 한다. 판정은 조건별 오차로 한다. 사이트 정보가 없는 자료
   (합성 데이터 등)에서는 예전처럼 기울기도 판정 기준이다.
   `--slope-role criterion`으로 예전 판정을 강제로 재현할 수 있다. 그때는 경고 문구가 붙는다.
3. **판정 근거를 출력에 남김**
   - 교란 분해: q–ΔT, N–ΔT, q–N 지수, 사이트당 열유속, 오차–사이트 순위상관
   - q″ 정의 민감도: 네 정의를 같은 게이트에 통과시킨 표
   - 기본·동등 후보 정의 사이에 판정이 갈리는지 표시

### 일부러 하지 않은 것

- **30% 기준을 옮기지 않았다.** 결과를 보고 기준을 바꾸면 게이트가 의미를 잃는다.
- **R_p를 튜닝하지 않았다.** 역산 R_p(0.41 → 0.10 µm)는 리포트에 진단용으로만 남긴다.
- **k_l 변형 정의를 고르지 않았다.** 그 정의로는 MAPE 27.1%로 통과하지만 보고서상 '참고' 정의다.
  보고서 원칙도 "결과가 좋아지는 정의만 선택하지 않는다"이다. 표에는 그대로 보인다.

## 4. 고친 뒤 결과

```
판정   : 불통과 (조건별 크기 이탈)
MAPE   : 32.6%  (기준 ≤ 30%; 조건별 이내 2/5)
기울기 : 0.700 ± 0.032  (참고만 — 사이트 수 처방 자료라 판정 제외)
```

- 판정 이유가 **"기울기 이탈"에서 "조건별 크기 이탈"로 바뀐다.** 더 이상 사이트 처방을 채점하지 않는다.
- 그래도 통과는 아니다. 조건별로 봐도 5개 중 3개가 ±30% 밖이다.
  오차가 사이트 처방을 따라간다는 것은 왜 벗어나는지에 대한 설명이지 판정을 바꿀 근거가 아니다.
- 동등 후보인 조화 정의로도 판정이 같다. 산술/조화 선택에 기대지 않는 결론이다.

## 5. 팀에서 정할 것

1. **이 결과의 표현** — "BubbleML 기준 Cooper 조건별 MAPE 32.6% (기준 30%), 기울기는 사이트
   처방 때문에 판정 불가"로 확정할지.
2. **기울기 검증 자료** — 형태(0.33)를 확인하려면 사이트 수가 물리로 정해지는 자료가 필요하다.
   예: FC-72 실제 표면 풀비등 실험.
3. **생성기 검증 모드의 ΔT** — 검증 모드에서는 사이트 수와 대기시간을 BubbleML 입력으로 준다.
   ΔT도 Cooper 역산값 대신 입력값(Twall − 58 °C)을 쓸지 정해야 한다. Cooper 역산값을 쓰면
   위의 −20~−43% 오차가 성장 계산으로 넘어간다.
4. **원본 CSV로 재실행** — 정답 기포장 레포가 비공개라 이번에는 보고서 PDF의 값으로 스냅숏을 만들었다.
   원본 `results/ground_truth_final.csv`를 받으면 아래 명령으로 다시 확인한다.
   ```bash
   python scripts/run_gate.py --config configs/ground_truth.yaml --ground-truth path/to/ground_truth_final.csv
   ```

## 6. HDF5 경로와 확정된 정의의 차이 (이번에는 고치지 않음)

정답 표 경로는 아래 차이의 영향을 받지 않는다. 그래도 `configs/default.yaml`로 HDF5에서 q″를
직접 뽑으면 정답 표와 다른 값이 나온다. 정답 보고서 4쪽 기준으로 맞춰야 할 것들이다.

| 항목 | 이 저장소 기본값 | 정답 보고서 |
|---|---|---|
| dfun 부호 | `φ>0` = 액체 | `dfun>0` = **증기** (뒤집히면 k_l·k_v가 바뀜) |
| 벽 기울기 차수 | 2차 | **1차** `2(T_w−T_1)/Δy` (Flash-X 경계와 같음) |
| Heaviside 폭 | 1.5·Δy | 1.5·√(Δx²+Δy²) |
| 히터 범위 | 바닥 전체 | 반폭 3.81997 mm, 엄격한 부등식 |
| 좌표 키 | `x`, `y` | `x_centers`, `y_centers` |
| T_sat | 56.6 °C | 58 °C |
